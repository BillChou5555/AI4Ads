# AI 智能广告信息流 App — 技术方案文档

## 项目概述

一款主打"极速体验"与"AI 内容理解"的单列广告信息流 Android App。核心价值：利用 AI 摘要与标签提升广告浏览效率，通过本地标签过滤与自然语言检索降低用户筛选门槛。

## 架构模式

采用 MVVM + Repository 模式，单向数据流（UDF）：

```
Fragment/Activity (UI)          ← 观察 LiveData/Flow，调用 ViewModel 方法
    ↑ LiveData/Flow 暴露
ViewModel (业务逻辑 + UI 状态)   ← 持有 Repository，在 viewModelScope 中发起协程
    ↑ suspend 调用
Repository (数据聚合与缓存)      ← 决定从网络还是本地取数据
    ↑              ↑
Remote (Retrofit)  Local (SQLiteOpenHelper)
```

**数据流向原则**：
- UI 层只做显示，不做业务判断
- ViewModel 持有所有 UI 状态，UI 通过观察 LiveData/Flow 被动更新
- Repository 是唯一的数据来源，ViewModel 不知道数据来自网络还是本地
- 网络请求在 `Dispatchers.IO` 上执行，由 Retrofit 的 `suspend` 函数自动处理

```sql
    position   TEXT,
    tag_name   TEXT
```

## 模块二：顶部 Tab 导航 (M2) ✅ 已实现

### 2.1 目标

实现 3 个频道的顶部 Tab 切换，支持点击切换和左右滑动切换。搜索按钮固定在 Tab 栏右侧。

### 2.2 核心架构：FeedFragment 与 FeedTabFragment 分离

M2 引入了两个不同的 Fragment，职责明确：

```
FeedFragment (宿主，由 NavHostFragment 管理)
  ├── TabLayout            ← 3 个 Tab 标签（精选/电商/本地）
  ├── ImageView            ← 看板入口（柱状图图标，M10 实现）
  ├── ImageView            ← 搜索入口（放大镜图标）
  └── ViewPager2           ← 承载 3 个子页面
        ├── FeedTabFragment(tab="featured")   ← 精选频道内容
        ├── FeedTabFragment(tab="ecommerce")  ← 电商频道内容
        └── FeedTabFragment(tab="local")      ← 本地频道内容
```

**为什么要拆成两个 Fragment？** ViewPager2 需要每页是一个独立的 Fragment。如果 FeedFragment 既当宿主又当子页面，会形成递归——每个子页面里再嵌套一套 TabLayout + ViewPager2。拆分后职责清晰：FeedFragment 只管导航，FeedTabFragment 只管内容。

### 2.3 技术方案

**TabLayout + ViewPager2 + FragmentStateAdapter**

- `TabLayout` 负责渲染 Tab 标签
- `ViewPager2` 负责页面滑动
- `TabLayoutMediator` 负责两者状态同步（点击 Tab → ViewPager2 翻页，滑动 ViewPager2 → Tab 跟随高亮）
- `FragmentStateAdapter` 负责为每个页面创建 `FeedTabFragment` 实例
- `offscreenPageLimit = 1`：预加载相邻 1 个页面的 Fragment

### 2.4 关键设计决策：TabLayout 放在哪里？

| 方案 | 位置 | 问题 |
|------|------|------|
| A（文档初版，未采纳） | `activity_main.xml` | 跳转到搜索/详情页时，Tab 栏依然可见 |
| **B（实际采用）** | `fragment_feed.xml` | 页面跳转时 Tab 栏自然消失 |

TabLayout 放在 FeedFragment 内部。当 Navigation Component 将 FeedFragment 替换为 SearchFragment 时，整个 FeedFragment 的布局（含 Tab 栏）自动退出屏幕。

### 2.7 FeedFragment — 宿主 Fragment

```kotlin
class FeedFragment : Fragment() {

    private var _binding: FragmentFeedBinding? = null
    private val binding get() = _binding!!

    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)

        // 1. 创建 Adapter，传入 this 使其使用 childFragmentManager
        val adapter = FeedPagerAdapter(this)
        binding.viewPager.adapter = adapter
        binding.viewPager.offscreenPageLimit = 1

        // 2. TabLayoutMediator 桥接两个控件
        TabLayoutMediator(binding.tabLayout, binding.viewPager) { tab, position ->
            tab.text = FeedPagerAdapter.TABS[position].label
        }.attach()

        // 3. 看板按钮 → 跳转数据看板（M10）
        binding.btnDashboard.setOnClickListener {
            findNavController().navigate(R.id.action_to_dashboard)
        }

        // 4. 搜索按钮 → 跳转搜索页（M13）
        binding.btnSearch.setOnClickListener {
            findNavController().navigate(R.id.action_to_search)
        }
    }

    override fun onDestroyView() {
        super.onDestroyView()
        _binding = null  // 防止内存泄漏
    }
}
```

### 2.8 FeedPagerAdapter — ViewPager2 的页面适配器

```kotlin
/**
 * FragmentStateAdapter 接收一个 Fragment 参数，
 * 内部调用 fragment.childFragmentManager。
 * 这意味着 ViewPager2 管理的子 Fragment 生命周期绑定到 FeedFragment。
 */
class FeedPagerAdapter(fragment: Fragment) : FragmentStateAdapter(fragment) {

    companion object {
        val TABS = listOf(
            TabInfo("featured", "精选"),
            TabInfo("ecommerce", "电商"),
            TabInfo("local", "本地")
        )
    }

    override fun getItemCount(): Int = TABS.size

    override fun createFragment(position: Int): Fragment {
        return FeedTabFragment.newInstance(TABS[position].key)
    }
}

data class TabInfo(val key: String, val label: String)
```

```kotlin
class FeedTabFragment : Fragment() {

    private val tab: String by lazy {
        arguments?.getString(ARG_TAB) ?: "featured"

}
```

## 模块三：信息流列表渲染 (M3)

### 3.1 目标

实现单列信息流 RecyclerView，支持 4 种卡片类型的自动判定与渲染，支持下拉刷新和上拉加载更多。

### 3.2 技术方案

**RecyclerView + ConcatAdapter + 4 种独立 Adapter**

每种卡片类型一个独立的 `RecyclerView.Adapter`，通过 `ConcatAdapter` 组合为一个整体 Adapter。好处：每个 Adapter 职责单一，便于独立修改某一种卡片的布局。

### 3.3 卡片类型自动判定

客户端根据广告数据自动判定使用哪种卡片：

```kotlin
enum class CardType {
    VIDEO,        // 有视频 URL
    MULTI_IMAGE,  // 图片数量 >= 2
    LARGE_IMAGE,  // 图片数量 == 1
    TEXT_ONLY     // 无图无视频
}

fun detectCardType(ad: Ad): CardType {
    return when {
        !ad.adVideoUrl.isNullOrEmpty() -> CardType.VIDEO
        ad.adImages.size >= 2          -> CardType.MULTI_IMAGE
        ad.adImages.size == 1          -> CardType.LARGE_IMAGE
        else                           -> CardType.TEXT_ONLY
    }
}
```

判定时机：在 Repository 拿到数据后、交给 Adapter 前，为每个 Ad 标注其 `cardType`。

### 3.10 FeedViewModel 状态管理

```kotlin
class FeedViewModel(
    private val repository: FeedRepository,
    private val tab: String
) : ViewModel() {

    // 数据
    private val _ads = MutableLiveData<List<Ad>>(emptyList())
    val ads: LiveData<List<Ad>> = _ads

    // 全部已加载的数据（未过滤）
    private val allAds = mutableListOf<Ad>()

    // 分页状态
    private var cursor: String? = null
    private var hasMore = true
    private val _isLoading = MutableLiveData(false)
    val isLoading: LiveData<Boolean> = _isLoading
    private val _isRefreshing = MutableLiveData(false)
    val isRefreshing: LiveData<Boolean> = _isRefreshing
    private val _error = MutableLiveData<String?>(null)
    val error: LiveData<String?> = _error

    // 标签过滤
    val activeFilterTags = MutableStateFlow<Set<String>>(emptySet())

    init {
        loadFirstPage()
        // 监听过滤标签变化，重新应用过滤
        viewModelScope.launch {
            activeFilterTags.collect { tags ->
                applyFilter(tags)
            }
        }
    }

    fun refresh() {
        cursor = null
        hasMore = true
        loadFirstPage()
    }

    fun loadMore() {
        if (_isLoading.value == true || !hasMore) return
        loadNextPage()
    }

    fun toggleFilterTag(tag: String) {
        val current = activeFilterTags.value.toMutableSet()
        if (tag in current) current.remove(tag) else current.add(tag)
        activeFilterTags.value = current
    }

    fun clearFilter() {
        activeFilterTags.value = emptySet()
    }

    private fun applyFilter(tags: Set<String>) {
        if (tags.isEmpty()) {
            _ads.value = allAds.toList()
        } else {
            _ads.value = allAds.filter { ad ->
                val tagValues = ad.aiTags.map { it.value }.toSet()
                tags.all { it in tagValues }
            }
        }
    }
}
```

## 模块四：视频播放器模块 (M4)

### 4.1 目标

实现 Feed 流中视频的自动静音播放、自动暂停，播放器实例池化复用，详情页复用同一播放器池。

### 4.2 核心概念

#### PlayerPool — 播放器实例池

- 全局单例
- 池大小 = `ceil(单屏可见卡片数 × 0.75)`，最小 2
- 两个队列：`idleQueue`（空闲可用）和 `busySet`（正在使用）
- `acquire()`：从空闲队列取出一个播放器，标记为 busy
- `release(player)`：重置播放器状态，放回空闲队列
- 池为空时 `acquire()` 创建新实例（不超过最大池大小）

```kotlin
class PlayerPool(private val context: Context, maxSize: Int = 3) {

    private val idlePlayers = ArrayDeque<ExoPlayer>(maxSize)
    private val busyPlayers = mutableSetOf<ExoPlayer>()

    fun acquire(): ExoPlayer {
        val player = if (idlePlayers.isNotEmpty()) {
            idlePlayers.removeFirst()
        } else {
            ExoPlayer.Builder(context).build().apply {
                volume = 0f  // 默认静音
                repeatMode = Player.REPEAT_MODE_ALL
            }
        }
        busyPlayers.add(player)
        return player
    }

    fun release(player: ExoPlayer) {
        player.stop()
        player.clearMediaItems()
        busyPlayers.remove(player)
        idlePlayers.addLast(player)
    }

    fun releaseAll() {
        busyPlayers.toList().forEach { release(it) }
    }
}
```

#### PlaybackManager — 播放调度器

- 驻留在 FeedTabFragment 中
- 监听 RecyclerView 滚动事件
- 每次滚动停止后执行 `evaluate()`：
  1. 遍历当前可见的 ViewHolder
  2. 计算每个卡片中心与屏幕中心的距离
  3. 距离在 ±25% 屏幕高度内 → 核心播放区
  4. 核心播放区内的视频卡片 → 挂载播放器 + 静音播放
  5. 不在核心播放区的 → 卸载播放器 + 暂停

```kotlin
class PlaybackManager(
    private val playerPool: PlayerPool,
    private val recyclerView: RecyclerView
) {
    private var activeViewHolder: VideoCardViewHolder? = null
    private var activePlayer: ExoPlayer? = null

    fun evaluate() {
        val screenHeight = recyclerView.height
        val screenCenter = screenHeight / 2
        val range = (screenHeight * 0.25f).toInt()

        // 找到最接近屏幕中心的视频 ViewHolder
        var bestViewHolder: VideoCardViewHolder? = null
        var bestDistance = Int.MAX_VALUE

        for (i in 0 until recyclerView.childCount) {
            val child = recyclerView.getChildAt(i)
            val holder = recyclerView.getChildViewHolder(child)
            if (holder is VideoCardViewHolder) {
                val cardCenterY = (child.top + child.bottom) / 2
                val distance = abs(cardCenterY - screenCenter)
                if (distance < bestDistance && distance <= range) {
                    bestDistance = distance
                    bestViewHolder = holder
                }
            }
        }

        // 切换播放器
        if (bestViewHolder != activeViewHolder) {
            // 归还旧播放器
            activePlayer?.let { playerPool.release(it) }
            activeViewHolder?.detachPlayer()

            // 分配新播放器
            if (bestViewHolder != null) {
                val player = playerPool.acquire()
                bestViewHolder.attachPlayer(player)
                player.play()
                activePlayer = player
            }
            activeViewHolder = bestViewHolder
        }
    }
}
```

### 4.3 详情页播放器复用

```
Feed 视频播放中
  → 用户点击卡片进入详情页
    → PlaybackManager 暂停 Feed 播放
    → 归还播放器到池
    → DetailFragment 从池中 acquire 新播放器
    → 挂载到详情页 PlayerView，有声音播放

用户从详情页返回
  → DetailFragment.onStop() 归还播放器
  → FeedTabFragment.onResume() 触发 PlaybackManager.evaluate()
  → 从池中 acquire → 恢复原视频静音播放
```

### 4.4 生命周期管理

| `FeedTabFragment.onResume()` | 触发 evaluate() |
| `FeedTabFragment.onPause()` | 暂停当前播放，归还播放器 |
| `FeedTabFragment.onDestroy()` | 释放池中所有播放器 |
| `DetailFragment.onResume()` | 从池获取播放器，挂载到 PlayerView |
| `DetailFragment.onPause()` | 归还播放器 |
| 滚动中（SCROLL_STATE_DRAGGING） | 暂停当前播放 |

### 5.1 目标

### 5.2 图片缓存 — Glide 配置

```kotlin
    .centerCrop()
    .placeholder(R.drawable.placeholder_image)          // 加载中占位图
    .error(R.drawable.placeholder_image)                // 加载失败占位图
    .into(imageView)
```

### 5.4 预加载策略

| 级别 | 机制 | 说明 |
|------|------|------|
| Tab 预加载 | `ViewPager2.offscreenPageLimit = 1` | 相邻 Tab 的 Fragment 提前创建，数据通过 Fragment 生命周期自动加载 |

| 首屏优先 | Glide `Priority.IMMEDIATE` | 当前可见项的图片优先加载 |

### 5.5 失败重试与降级

| 场景 | 策略 | 实现位置 |
|------|------|----------|
| 图片加载失败 | Glide 自动重试 3 次，失败后显示本地占位图 | ViewHolder.onBind() 中 `.error(R.drawable.placeholder)` |

## 模块七：标签本地过滤 (M7)

### 7.1 目标

### 7.2 交互流程

```
初始状态：activeFilterTags = {}，显示全部已加载的广告

用户点击"运动"标签
  → activeFilterTags = {"运动"}
  → 遍历已加载广告，保留 ad.aiTags 中同时包含"运动"的

用户再次点击"运动"（已选中）
  → activeFilterTags = {"春季新品"}
  → 恢复只有"春季新品"的过滤条件

用户点击"清除全部"
  → activeFilterTags = {}
  → 全部恢复 VISIBLE
```

### 7.4 关键边界

| 场景 | 行为 |
|------|------|
| 切换 Tab | **自动清除过滤状态**（`activeFilterTags = {}`，FilterBar 隐藏） |
| 下拉刷新 | **不清除过滤**，新数据回来后在 ViewModel 中自动重新应用过滤 |
| 上拉加载更多 | 新追加的数据自动应用当前过滤条件 |

```kotlin
// 方式 A（推荐）：通过 Adapter 过滤，但用 DiffUtil 保证位置不变

fun applyFilter(tags: Set<String>) {
    if (tags.isEmpty()) {
        adapter.submitList(allAds)
    } else {
        val filtered = allAds.filter { ad ->
            val tagValues = ad.aiTags.map { it.value }.toSet()
            tags.all { it in tagValues }
        }
        adapter.submitList(filtered)
    }
}
```

```kotlin
class AnalyticsManager(
    private val database: DatabaseHelper,
    private val deviceIdProvider: DeviceIdProvider
) {
    private val exposedAdIds = mutableSetOf<String>()  // 曝光去重

    fun trackImpression(ad: Ad, tab: String) {
        if (ad.adId in exposedAdIds) return
        exposedAdIds.add(ad.adId)
        database.insertAnalyticsEvent(
            deviceId = deviceIdProvider.deviceId,
            adId = ad.adId,
            eventType = "impression",
            eventTime = System.currentTimeMillis(),
            tab = tab
        )
    }
    // trackClick / trackLike / trackFavorite / trackShare / trackTagFilter 同理
    // 非曝光事件不经过去重检查，直接写入

    // 查询方法供看板使用
    fun getEventCountsByType(): Map<String, Int> = database.getEventCountsByType()
    fun getAllEvents(): List<DatabaseHelper.AnalyticsEventRecord> = database.getAllEvents()
}
```

```kotlin
    private val searchApi: SearchApi,
    private val database: DatabaseHelper
) : ViewModel() {

    // 搜索状态
    private val _searchState = MutableLiveData<SearchUiState>(SearchUiState.Idle)
    val searchState: LiveData<SearchUiState> = _searchState

    // 搜索历史
    private val _history = MutableLiveData<List<String>>(emptyList())
    val history: LiveData<List<String>> = _history

    // 搜索结果
    private val _results = MutableLiveData<List<Ad>>(emptyList())
    val results: LiveData<List<Ad>> = _results

    init {
        loadHistory()
    }

    fun search(query: String) {
        if (query.isBlank()) return
        _searchState.value = SearchUiState.Loading
        database.insertSearchHistory(query)
        loadHistory()

        viewModelScope.launch {
            try {
                val response = searchApi.search(query)
                _results.value = response.items
                _searchState.value = if (response.items.isEmpty()) {
                    SearchUiState.Empty("未找到相关广告")
                } else {
                    SearchUiState.Success(response.items)
                }
            } catch (e: Exception) {
                _searchState.value = SearchUiState.Error("搜索失败，请重试")
            }
        }
    }

    fun clearHistory() {
        database.clearSearchHistory()
        _history.value = emptyList()
    }

    private fun loadHistory() {
        _history.value = database.getSearchHistory()
    }
}

sealed class SearchState {
    object Idle : SearchState()
    object Loading : SearchState()
    data class Success(val items: List<Ad>) : SearchState()
    data class Empty(val message: String) : SearchState()
    data class Error(val message: String) : SearchState()
}
```

### 13.7 搜索结果交互保持一致

搜索结果复用 Feed 卡片的全部交互：
