# AI 智能广告信息流 App — 技术方案文档

## 项目概述

一款主打"极速体验"与"AI 内容理解"的单列广告信息流 Android App。核心价值：利用 AI 摘要与标签提升广告浏览效率，通过本地标签过滤与自然语言检索降低用户筛选门槛。

## 技术栈总览

| 类别 | 选型 | 说明 |
|------|------|------|
| 语言 | Kotlin | |
| 最低 SDK | API 24 (Android 7.0) | |
| UI 框架 | XML View | RecyclerView ViewHolder 复用机制成熟 |
| 构建工具 | Gradle (Kotlin DSL) | |
| 网络请求 | Retrofit 2 + OkHttp + Gson | |
| 图片加载 | Glide | 自带内存+磁盘双级缓存 |
| 视频播放 | ExoPlayer (Media3) | Google 官方推荐 |
| 本地持久化 | SQLiteOpenHelper | 点赞/收藏/转发状态、搜索历史 |
| 响应式 | Kotlin Coroutines + Flow + LiveData | |
| 依赖注入 | 手动 DI (AppContainer) | |
| 导航 | Navigation Component | 单 Activity 架构 |

## 架构模式

采用 MVVM + Repository 模式，单向数据流（UDF）：

```
Fragment/Activity (UI)
    ↑ LiveData/Flow 观察
ViewModel (业务逻辑 + UI 状态管理)
    ↑ suspend 调用
Repository (数据聚合与缓存策略)
    ↑         ↑
Remote       Local
(Retrofit)   (SQLite)
```

- 搜索按钮固定在 TabLayout 右侧，点击跳转搜索页

## 模块三：信息流列表渲染 (M3)

### 方案

- **RecyclerView + ConcatAdapter**：多 ViewType 通过 ConcatAdapter 组合，每种卡片类型独立 Adapter
- **客户端自动判定卡片类型**：

```kotlin
fun detectCardType(ad: Ad): CardType {
    return when {
        !ad.adVideoUrl.isNullOrEmpty() -> CardType.VIDEO
        ad.adImages.size >= 2 -> CardType.MULTI_IMAGE
        ad.adImages.size == 1 -> CardType.LARGE_IMAGE
        else -> CardType.TEXT_ONLY
    }
}
```

### 卡片布局

```
┌─────────────────────────────┐
│                             │
│   大图 / 多图网格 / 视频封面  │
│                             │
├─────────────────────────────┤
│  广告标题                    │
│  AI 摘要（副标题，灰色）      │
│  [标签1] [标签2] [标签3]     │  ← ChipGroup
│  ♡ 赞  ☆ 收藏  ↗ 转发      │
└─────────────────────────────┘
```

### 分页策略

- **cursor-based 分页**，对齐服务端 `created_at DESC` 排序
- 下拉刷新 → 清空 cursor，请求第一页，替换列表
- 上拉加载 → 使用当前 cursor，请求下一页，追加列表
- `X-Device-ID` 通过 OkHttp Interceptor 统一注入

### 卡片点击

- 非交互区（根布局）点击 → 跳转详情页
- 标签、按钮等交互区消费事件，阻止冒泡

## 模块四：视频播放器模块 (M4)

### 播放器池

- 全局单例 `PlayerPool`，池大小 = `ceil(屏幕可见卡片数 × 0.75)`，最小 2
- ExoPlayer 实例统一借还，不新建/销毁

```
PlayerPool
├── acquire(): ExoPlayer   // 从空闲队列取出
└── release(player)        // 归还到空闲队列，重置状态
```

### 播放调度

`PlaybackManager` 统一调度 Feed 和详情页的播放行为：

```
RecyclerView.onScrollListener
  → PlaybackManager.evaluate()
    → 遍历可见 ViewHolder
      → 计算卡片中心与屏幕中心的距离
        → 处于核心播放区(±25%) → attach + 静音播放
        → 不在核心播放区 → detach + pause
```

### 核心播放区判定

```kotlin
fun isInPlayArea(cardCenterY: Int, screenHeight: Int): Boolean {
    val screenCenter = screenHeight / 2
    val range = (screenHeight * 0.25f).toInt()
    return abs(cardCenterY - screenCenter) <= range
}
```

### 详情页复用

- 从 Feed 进入详情页：暂停 Feed 播放 → 归还播放器 → 详情页从池中获取 → 播放详情视频
- 从详情页返回 Feed：归还详情页播放器 → Feed 重新获取 → 恢复原视频播放

## 模块五：性能优化与缓存 (M5)

### 图片缓存

Glide 默认 LruCache（内存）+ DiskCache（磁盘），首屏优先：

```kotlin
Glide.with(context)
    .load(url)
    .priority(Priority.IMMEDIATE)  // 可见区域优先
    .diskCacheStrategy(DiskCacheStrategy.ALL)
    .centerCrop()
    .into(imageView)
```

### 视频首帧缓存

ExoPlayer 自带 `CacheDataSource.Factory`，首帧加载后磁盘缓存，避免重复下载。

### 预渲染

- **Tab 级别**：`ViewPager2.offscreenPageLimit = 1`，当前 Tab 时自动创建相邻 Tab 的 Fragment
- **列表级别**：`LinearLayoutManager.initialPrefetchItemCount` 触发 Glide 图片预加载

### 失败重试与降级

| 场景 | 策略 |
|------|------|
| 图片加载失败 | Glide 默认重试 3 次，最终降级为本地占位图 |
| 网络请求失败 | ViewModel 捕获异常，保留已有数据，SnackBar 提示 |
| 网络不可用 | 显示缓存数据，状态栏提示离线 |

## 模块七：标签本地过滤 (M7)

### 交互流程

```
点击标签"运动" → activeFilterTags = {"运动"}
  → 遍历已加载的 Ad 列表
    → ad.aiTags 包含所有 activeFilterTags → VISIBLE
    → ad.aiTags 不包含任意 activeFilterTags → GONE

再点击"春季新品" → activeFilterTags = {"运动", "春季新品"}
  → AND 逻辑：必须同时包含两个标签

再次点击"运动"(已选中) → activeFilterTags = {"春季新品"}（移除）

点击"清除全部" → activeFilterTags = {} → 全部恢复 VISIBLE
```

### 过滤提示条

```
┌─────────────────────────────────────────────┐
│  当前筛选：[运动 ×] [春季新品 ×]  清除全部   │
└─────────────────────────────────────────────┘
```

在 RecyclerView 上方，筛选激活时显示，无筛选时隐藏。

### 状态管理

```kotlin
// FeedViewModel
val activeFilterTags: MutableStateFlow<Set<String>> = MutableStateFlow(emptySet())

fun toggleFilterTag(tag: String) {
    val current = activeFilterTags.value.toMutableSet()
    if (tag in current) current.remove(tag) else current.add(tag)
    activeFilterTags.value = current
    // 触发 Adapter 重新过滤
}

fun clearFilter() {
    activeFilterTags.value = emptySet()
}
```

### 重要边界

- 切换 Tab → 自动清除过滤状态
- 下拉刷新 → 不清除过滤，新数据回来后自动重新应用过滤

- 入场动画：页面从右向左滑入覆盖 Feed
- 出场动画：页面从左向右滑出（返回手势或系统返回键）

```
│  ┌──HorizontalViewPager2─────┐ │
```

### 媒体浏览

- `HorizontalViewPager2` + 小圆点指示器（TabLayout + TabLayoutMediator）
- 媒体列表 = `ad_images` + `ad_video_audio` 合并
- 当前页为视频时，从播放器池获取播放器挂载

### 视频控制

- 使用 ExoPlayer `PlayerView`，`useController = true` 获得控制 UI
- 点击媒体区域 → 显示/隐藏控制栏（播放/暂停、进度条 SeekBar、音量 SeekBar）

### 左滑返回手势（跟手动画）

- 自定义手势检测：仅当 `HorizontalViewPager2` 在第一页 + 触摸起点在屏幕左边缘 30dp 内时触发
- `rootView.translateX` 实时跟随手指
- 松手判断：
  - 滑动距离 > 1/3 屏幕宽 → 触发 `popBackStack`
  - 滑动距离 < 1/3 屏幕宽 → `ObjectAnimator` 回弹到原位

### 返回位置保持

- Feed RecyclerView 的滚动位置由 Fragment 生命周期自动保存/恢复
- 视频播放由 PlaybackManager 在 `onResume` 时重新调度

## 模块十一：物料入库与 AI 预处理 (M11)

**服务端已有，客户端无需实现。**

核心流程：
1. 广告商通过 `POST /api/v1/ads/upload` 上传广告数据
2. content_hash (MD5 of title+provider+ad_text) 去重
3. Celery 异步触发 AI 管线：LLM 生成摘要 + 智能标签提取 + 标签语义去重
4. BGE Embedding 向量化存入 pgvector

## 模块十二：信息流分发与自然语言搜索 (M12)

**服务端已有，客户端无需实现。**

### Feed 分发

- `GET /api/v1/ads/feed?tab=&size=&cursor=`
- cursor-based 分页，`created_at DESC` 排序
- Redis 缓存首页（TTL 5min）
- 基于 `X-Device-ID` 的曝光排重

### RAG 搜索链路

```
用户输入 → BGE Embedding 向量化
  → pgvector Cosine 检索 Top-50 (相似度 ≥ 0.2)
  → LLM 逐条精排 (≥ 0.6 保留)
  → 分页返回
```

降级：向量检索或 LLM 不可用时 → 关键词标签模糊匹配。

## 模块十三：自然语言搜索页 (M13)

### 入口

TabLayout 右侧搜索图标按钮，点击跳转搜索页。

### 页面结构

```
┌────────────────────────────────────┐
│  ← 返回    搜索框 [_________] 🔍  │  ← 顶部搜索栏
├────────────────────────────────────┤
│  [未输入时]                         │
│  历史搜索                           │
│  性价比运动鞋                        │
│  夏季连衣裙                          │
│  清空历史                           │
├────────────────────────────────────┤
│  [搜索中]                           │
│  Loading 动画                       │
├────────────────────────────────────┤
│  [有结果时]                         │
│  RecyclerView (复用 Feed 卡片)      │
│  交互与 Feed 完全一致               │
└────────────────────────────────────┘
```

### 搜索流程

```
输入关键词 → 点击搜索按钮 / 键盘回车
  → SearchViewModel.search(query)
    → 显示 Loading
    → GET /api/v1/ads/search?q=xxx
    → 成功 → 隐藏 Loading，展示结果
    → 失败 → 隐藏 Loading，SnackBar 提示
```

### 技术要点

- **结果展示**：直接复用 Feed 的 Adapter，支持大图/多图/视频三种卡片样式
- **交互一致**：标签点击过滤、点赞/收藏/转发、点击进入详情页全部复用
- **全量返回**：结果无分页，一次性展示
- **搜索历史**：SQLite 本地持久化，最多保存最近 10 条，支持清空
- **键盘处理**：搜索框自动聚焦，`IME_ACTION_SEARCH` 触发搜索，结果展示后收起键盘

### 状态管理

